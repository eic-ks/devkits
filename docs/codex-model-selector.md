# Codexモデル選択ツールの仕様

この仕様は、モデル選択ツールの実装が完了するまで有効です。実装後は必要な受け入れ条件をコードやテストに移し、この文書を削除してください。調査履歴や経緯は保存しません。

## 目的と構成

- `cx` を単独で使えるCodex起動コマンドとして提供し、将来は `dev agent model` から同じ機能を呼び出せるようにする。
- Bashを基本にし、JSON処理にjq、対話選択にfzfを使う。miseは任意の依存管理手段とし、実行要件にしない。
- モデル取得、候補表示、引数処理・起動を分離する。

## モデル一覧

- 第一候補は `codex debug models`。CLI側でExperimental扱いのため、JSON形式の検証と分かりやすい非互換エラーを用意する。
- `models[]` の `slug` を起動用ID、`display_name` を表示名、`description` を任意の説明に使う。初期候補は `visibility == "list"` とする。
- raw JSONをそのまま表示・保存しない。許可したフィールドだけを出力し、内部指示文などを除外する。
- `codex debug models --bundled` は明示された場合のオフライン代替にする。取得失敗時に古い候補へ無言で切り替えない。
- Codex内部キャッシュや非公開エンドポイントは使わない。独自の永続キャッシュも初期実装には加えない。
- `/model` の表示候補と完全一致するかは未確認。実セッションで確認するまでは一致を保証しない。

## コマンドと起動動作

```text
cx [CODEX-ARGS...]
cx --bundled [CODEX-ARGS...]
cx resume [--last | SESSION_ID] [CODEX-ARGS...]
cx models [--json] [--bundled]
cx doctor
```

- `cx` はfzfでモデルを選び、`codex -m MODEL` として起動する。resume時は `codex resume ... -m MODEL` を使う。
- `cx --bundled` は同梱カタログを明示的に使って選択する。
- `-m MODEL`、`--model MODEL`、`--model=MODEL` が指定された場合は選択を省き、引数をそのままCodexへ渡す。
- `--help`、`-h`、`--version` はモデル取得や選択を行わずCodexへ渡す。
- 引数配列を保ったまま `exec` し、現在の作業ディレクトリとCodexの終了コードを維持する。`eval` は使わない。
- EscまたはCtrl+Cによる選択キャンセル時はCodexを起動しない。
- ラッパーはCodexの設定ファイル、シェル設定、キャッシュを変更しない。選択モデルは起動時引数として指定する。
- `cx models --json` はraw形式に依存しない、安全なフィールドだけのJSONを返す。

## 受け入れ条件

- jqでJSONの形式と必須フィールドを検査し、未知の追加フィールドは無視する。
- hidden項目、不正なID、候補ゼロ、取得失敗を区別して扱う。
- Codexとfzfをモック化し、モデルIDと表示名の対応、空白を含む引数、作業ディレクトリ、明示モデルの優先、help/versionの迂回、キャンセル、終了コードを確認する。
- 一時的なCodex設定領域を使ったテストで、起動前後の設定ファイルが変化しないことを確認する。
- macOSとUbuntu/WSL2で確認する。実セッションで `/model` との候補差、`-m` の反映、設定ファイルへの副作用、resume時のモデル切替も確認する。

## エラー時の動作

- Codex、jq、fzfの不足は必要なコマンド名を英語で示す。
- 取得不能、JSON不正、CLI非互換は非ゼロで終了し、raw JSONや秘密情報をログに出さない。
- 同梱一覧への切り替えはユーザーの明示選択とし、取得元を表示する。
